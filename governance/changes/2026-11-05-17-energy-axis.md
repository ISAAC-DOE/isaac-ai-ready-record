# 2026-11-05-17 How a spectrum's energy axis was aligned and calibrated

- **Product:** repository (schema, validator, wiki, record contract). **Kind:** schema (additive, optional
  block), validator (warnings), wiki, contract 2026-11-05.1. **Owner:** D. Sokaras (PI). **Co-designer:**
  O. Paredes Mellone (OCEAN). **Status:** phase 1 shipped in #291 (portal v0.0.375, contract 2026-11-05.1) as warnings; PI approved
  2026-11-05. Phase 2 (the alignment endpoint, section 4) is a later change.

## Problem

A computed spectrum has no absolute energy. OCEAN writes E_rel = E_abs - C, where C is the core offset the run
used; a series is comparable only when its members share one C taken from an anchor, and a series is placed on
the experimental axis by one calibration against a standard. Today a record can only say this in prose
(`computation.energy_reference`) or in an open namespace (`system.configuration.ocean.alignment`), so:
- no reader can check whether two spectra may be compared, or by how much their energies can be trusted;
- the same question arises for measured spectra (a monochromator calibrated on a Cu foil), with no field either;
- the five OCEAN MnF records in ISAAC carry the chain only as text.

## What the co-designer established (2026-11-04, OCEAN 3.2.0.1)

1. **Gauge.** Directly comparable only if these match: the anchor's core offset C; the functional, with U as
   part of it (U can select a different electronic basin); the absorber pseudopotential; the screening radius
   (r >= 9 Bohr for absolute offsets); the core-hole treatment (full or half) and the screening model with its
   scale factor (`scfac`). For differentials, also identical broadening. Recorded but not required to match:
   the dielectric constant (set per compound on purpose), k-grids, band counts, cell size, the code's minor
   version (match on the major version).
2. **`total_offset` in OCEAN's core_shift.log is diagnostic only** and must never be added to the axis: the
   spectrum already contains it.
3. **Calibration:** one standard per (series, edge, functional), one constant shift, and a REQUIRED feature
   definition (on MnF the definition alone moves the MnF2-MnF3 shift by 1.5 eV). Examples: F K on LiF's first
   peak at 693.8 eV; Cu K on the Cu-foil first inflection at 8979 eV; O K aligned to XRS on the centre of mass
   over 536-542 eV. Uncertainty has two parts: the experiment's own, and the broadening-sweep half-range.
   Live example (Cu K, 2026-11-05, records in ISAAC): PBE and r2SCAN series, each with its own anchor (C = 151.663
   and 156.633), both calibrated on the Cu-foil first inflection at 8979.0 eV. On the 10%-onset definition r2SCAN
   is closer to experiment (CuO - Cu: PBE 4.18 +/- 0.08, r2SCAN 4.61 +/- 0.07, measured 4.50); on the September
   benchmark's edge definition PBE+U was closer. The feature definition decides which functional "wins".
4. **Several anchors per project are common:** two functionals tied by a measured shift (PBE vs r2SCAN anchors
   on Li2MnO3 O K, first peak: -3.64 eV); one anchor per edge in multi-edge projects; two anchors for one edge
   (two LiF anchors 70 meV apart), so an anchor is a link to a record, not a number; overlapping edges in one
   scan sharing one calibration.
5. **Comparison through a proxy is how the work is done**, with four refinements: uncertainties add in
   quadrature only over independent links (a link both spectra share cancels); each hop between different cells
   (other compounds, or the same compound in another supercell) adds a residual of about 0.1-0.5 eV even in one
   gauge; a tie is valid for the compound, edge and feature it was
   measured on, and using it elsewhere adds that residual; every tie and calibration carries its feature
   definition.

## Proposed change

### 1. One optional block, `measurement.energy_axis` (measured and computed spectra alike)

Example: the MnF2 F K spectrum in ISAAC (`01M6M0DY2ASW47QQARCCEFS2AA`), calibrated through its LiF anchor.

```json
"energy_axis": {
  "status": "absolute_calibrated",
  "gauge": {
    "anchor_record_id": "01M6M0DY2AEK6RG8HV410VJ5GA",
    "core_offset_eV": 137.129,
    "core_offset_source": "computed on the LiF anchor (64-atom cell) at r = 9.5 Bohr, then frozen for the series",
    "functional": "PBE+U (Mn 1.5 eV)",
    "magnetic_state": "AFM (rutile ground-state ordering)",
    "absorber_pseudopotential": "<OCEAN pp database id for F>",
    "core_level_projectors": "<OPF source for the F 1s core-hole potential>",
    "screening_radius_bohr": 9.5,
    "screening_grid_rmax_bohr": 12.0,
    "core_hole": "full",
    "screening_model": "RPA",
    "screening_scale_factor": 0.8,
    "code_major_version": "OCEAN 3",
    "total_offset_added_to_axis": false
  },
  "calibration": {
    "standard": "LiF",
    "standard_record_id": null,
    "standard_detection_mode": "TEY",
    "feature": {"name": "first_peak", "definition": "first resolved peak >= 0.6 x maximum, at the experiment-matched broadening"},
    "reference_value_eV": 693.8,
    "reference_source": "Roy/Cabana, Chem. Mater. 2023, 35, 2107",
    "shift_applied_eV": 548.02,
    "uncertainty": {"experimental_eV": null, "broadening_sweep_eV": 0.2}
  },
  "ties": [
    {"to_record_id": "<ULID of the r2SCAN anchor>", "offset_eV": -3.64, "sigma_eV": null,
     "scope": {"compound": "Li2MnO3", "edge": "O K",
               "feature": {"name": "first_peak", "definition": "..."}},
     "notes": "PBE -> r2SCAN anchor tie, measured on this compound and edge only; sigma not yet measured"}
  ]
}
```

Field definitions that carry the most risk of misuse:
- **`shift_applied_eV`** maps the axis before calibration to the absolute one: `E_abs = E_before + shift_applied_eV`.
  For a computed spectrum `E_before` is the code's energy with the core offset added back; for OCEAN, the absspct
  energy plus `C = gauge.core_offset_eV` (the skill computes `E_abs = x + C + shift`); for MnF the shift is
  +548.02 eV. For a measured spectrum `E_before` is the monochromator reading. The definition states the sign
  and the starting axis.
- **`core_offset_eV`** is the value this record's run used, frozen from the anchor named in `anchor_record_id`.
  Two anchors of one compound can differ (the two 64-atom LiF anchors, 137.059 and 137.129 eV), so the anchor is
  a record, never a number alone.
- **`magnetic_state`** (non-spin-polarized, FM, which AFM ordering) is part of the gauge: with the functional and U
  it selects the electronic basin.
- **`absorber_pseudopotential` and `core_level_projectors`:** OCEAN builds core-level projectors (OPF) for the
  absorber, and they set the core-hole potential; both are recorded.
- **`screening_grid_rmax_bohr`** must exceed the screening shells by more than 2 Bohr (a warning otherwise).
- **HERFD detection** goes in `energy_axis.detection` {`mode`, `emission_line` (Ka1, Kb1,3, La1, ...),
  `emission_energy_eV`, `analyzer` (crystal, reflection), `incident_resolution_eV`, `analyzer_resolution_eV`}.
  The effective Lorentzian depends on the final-state width, and sharper HERFD features move first-inflection and
  first-peak positions. (Drafted under `calibration`; moved in review, since they describe how the sample was
  detected and a foil measured in transmission has no analyzer.)
- **`standard_detection_mode`** (transmission, TFY, TEY, HERFD, ...): the standard is often measured in another
  mode than the sample, and a shift between modes would otherwise go unrecorded.

A measured spectrum uses `status` and `calibration` (no `gauge`): the standard, its detection mode, the feature
(for example the first inflection of the Cu-foil K edge), the reference energy and its source.
`computation.energy_reference` stays as a one-line human summary.

### 2. Method family and a spectroscopy block

- `computation.method.family` gains `BSE`, `multiple_scattering` (FEFF) and `multiplet` (CTM4XAS, Quanty), cheap and
  additive. `BSE` requires `core_hole_treatment` and `functional_name`. The gauge fields above are defined for
  `BSE` only: FEFF's E0 and core-hole conventions differ, and their fields wait until records exist.
- `computation.spectroscopy`: `edge` (element, shell, label), `broadening` (mode conventional | HERFD,
  `lorentzian_hwhm_eV`, `gaussian_fwhm_eV`, a source for every width, the sweep), `site_average`. Settings that
  live today in `system.configuration.ocean` move here.

### 3. Validator checks (all start as warnings)

| Code | Tier | When |
|---|---|---|
| `TOTAL_OFFSET_ADDED_TO_AXIS` | warning (an error only after gate 6) | `gauge.total_offset_added_to_axis` is true |
| `ENERGY_AXIS_NOT_STATED` | warning | a computed X-ray spectrum carries an absolute `edge_position`, `white_line_energy`, `inflection_point_energy` or `peak_position` (eV) and no `energy_axis` (first drafted as `ABSOLUTE_ENERGY_UNCALIBRATED`, firing on any status but `absolute_calibrated`; changed in review) |
| `GAUGE_INCOMPLETE` | warning | a `BSE` spectrum `aligned` or `absolute_calibrated` without `anchor_record_id`, `core_offset_eV` or `functional` (added in review) |
| `CALIBRATION_INCOMPLETE` | warning | `absolute_calibrated` without standard, `feature.definition`, `reference_value_eV` and `reference_source` |
| `TIE_WITHOUT_SCOPE` | warning | a tie without compound, edge and feature definition |
| `SCREENING_RADII_NOT_COMPARABLE` | warning, at the API | two spectra compared with different screening radii when either is below 9 Bohr (no warning when both are at least 9 Bohr, or equal) |
| `SCREENING_GRID_TOO_SMALL` | warning | `screening_grid_rmax_bohr` not more than 2 Bohr beyond the screening shells |
| `DIFFERENTIAL_NOT_ALIGNED` | warning, at the API | a differential's `relative_to` record has no alignment path to this record (below) |

### 4. Comparison through a proxy, at the API (phase 2)

`GET /portal/api/records/{a}/alignment?to={b}` returns the path between two spectra, its total offset and its
uncertainty. Nodes are records; edges are a shared anchor and gauge, a shared calibration standard and
feature, or a tie. The path is taken from the two records' closest common node, so links both share cancel.
Each hop between different cells adds a residual: different compounds, and also the same compound in a different
supercell (8- and 64-atom LiF computed core offsets 9.4 eV apart; only a frozen C makes them comparable, and
intensities still differ by about 20%). The default residual is 0.3 eV for every edge, overridable per gauge; the
one direct measurement (O K across many LixMn4O12 cells in one gauge) gives sd 0.21 eV with no composition trend.
Per-edge defaults come later, from records. A tie used outside its scope adds the residual too. The response
reports the numerical part (sweep sigmas) and the transfer residual separately. The same function serves `DIFFERENTIAL_NOT_ALIGNED`.

### 5. Links

`calibration_of` is documented as "this record calibrates the target" (the anchor points at the records it
calibrates), which is what the stored MnF records already do. The anchor is also named inside each calibrated
record (`gauge.anchor_record_id`), so a reader of either record finds the other.

## Phase 1 as built

- Schema: `measurement.energy_axis` {`status` (required: `as_recorded`, `aligned`, `absolute_calibrated`; it
  describes the axis the record stores), `detection`, `gauge`, `calibration`, `ties`, `notes`}, with the fields of
  section 1 plus `gauge.transfer_residual_eV` and `calibration.standard_acquisition`; the HERFD fields moved from
  `calibration` to `detection` in review;
  `computation.spectroscopy` {`edge`, `broadening` (`mode`, widths with sources, `sweep`), `site_average`};
  method families `BSE`, `multiple_scattering`, `multiplet`. Only `status`, and a tie's `to_record_id` and
  `offset_eV`, are required by the schema: a missing feature definition or scope is a warning, so a record is
  never rejected for an incomplete block.
- Vocabulary: `measurement.energy_axis.status`, `measurement.energy_axis.gauge.core_hole`,
  `computation.spectroscopy.broadening.mode`; `BSE` requires `functional_name` and `core_hole_treatment`
  (`not_reported` accepted), like every family in `computation.method_requirements_by_family`.
- Validator: six warnings (section 3 minus the two API checks of phase 2, plus `GAUGE_INCOMPLETE` from review). `TOTAL_OFFSET_ADDED_TO_AXIS` starts
  as a warning like every new check (gate 4); promotion to an error is a gate-6 decision. The messages name no
  simulation code (the validator stays code-agnostic).
- Documentation: Measurement section 3.4 (the block, both examples), Computation section 7.7 (families and the
  spectroscopy block), the `calibration_of` row on Links, contract step 9 and a new contract example, the
  generated Validation-Rules, Constraint-Matrix, vocabulary appendices and schema diagram, README. Undocumented
  schema fields fell from 37 to 34 (baseline ratcheted).
- Examples: new `examples/ocean_xas_calibrated_record.json` (computed Cu K of CuO, gauge and calibration);
  calibration blocks added to `ex_situ_xanes_cuo2_record.json` (measured HERFD, Cu foil in transmission) and to
  `simulation_xas_record.json` (which the new check would otherwise flag). All three publish with no warning.

## Review (gate 2, 2026-11-05)

codex, gemini and grok, blind, on the design, the schema fields, the checks, the wiki text, contract step 9 and
the examples (packet in the PI's review archive). Edison could not run: its API key has expired.

- **All three:** the HERFD settings under `calibration` describe the sample's detection, so a foil measured in
  transmission appeared to have an analyzer. Moved to `energy_axis.detection` {`mode`, emission line and energy,
  analyzer, resolutions}; `standard_detection_mode` stays with the standard.
- **All three:** a computed calibration without its shift passed silently (the XSpectra example had none).
  `CALIBRATION_INCOMPLETE` now asks a calculation for `shift_applied_eV`; the example states one.
- **codex, grok:** the gauge mixed series identity with each record's run (the CuO example's AFM state on a Cu
  metal anchor), and the "must match" list wrongly included settings that differ across a series. Now: anchor,
  core offset and source identify the series; every other gauge field is this record's run; spectra share a gauge
  with one base functional, the same U on shared species, and the same absorber, screening, core hole and code
  major version. Contract step 9 asks for a gauge from BSE series only.
- **gemini, grok:** the first check fired on stated `aligned` and `as_recorded` axes, which an uploader whose
  source gives no calibration cannot clear, and on a DFT `peak_position` with no spectrum. Renamed
  `ENERGY_AXIS_NOT_STATED`: it fires only when a computed X-ray spectrum has no block. Contract step 9 no longer
  reads as "report an absolute energy only with its calibration" (which drops values): the value is kept with
  `as_recorded` and the gap in notes.
- **codex:** a BSE spectrum can claim a shared axis with no anchor. Added `GAUGE_INCOMPLETE`. A foil recorded in
  the same scan differs from an external one: added `calibration.standard_acquisition`.
- **gemini, codex:** the stored axis was ambiguous (before or after the shift). `status` now describes the axis the
  record stores, and the stored energies are after the shift.
- **grok, gemini:** the Cu reference was cited loosely. Bearden and Burr tabulate the Cu K absorption edge; measured
  foil inflections differ by more than 1 eV (Kraft et al. 1996). The examples say what the value is, and the
  `reference_source` text says why it must be named.
- **grok:** a differential needs no absolute calibration only with the same broadening and feature definition; a
  shared calibration cancels only with the same standard, definition and detection mode; the example located the
  feature "at the broadening of this record", which gives each member its own shift (now "once, at the series'
  nominal broadening"); Lorentzian widths are half widths. All adopted.
- **grok** also read the drafted shift definition (`E - C` as the starting axis) as contradicting the MnF numbers;
  the same error was corrected before the review returned (section 1).
- **Not adopted, with reasons:** placing `gauge` under `computation` (gemini): the block keeps the axis and the
  settings that define it together, for measured and computed spectra alike. Mirroring the anchor into `links` on
  each member (gemini): the anchor carries `calibration_of`, and a link declared from both ends is the pattern the
  repository discourages. Scaling the 0.3 eV residual by edge energy (gemini): the co-designer's one measurement
  does not support a scale yet; per-edge values come from records. Suppressing `CALIBRATION_INCOMPLETE` when notes
  explain a gap (gemini): a missing definition is a real gap, and a warning that stays is an accepted outcome.
- **For phase 2** (the alignment endpoint): treat `broadening_sweep_eV` as a half range (sigma = half range / sqrt 3
  for a uniform bound); count each distinct change of cell once (sigma^2 = sum of independent sigma^2 + n_cell x
  residual^2); identify a shared link by its anchor record or by (standard, feature definition, reference source,
  detection mode). Candidate check: `feature_energy_before_shift_eV` plus `shift_applied_eV` equals
  `reference_value_eV` (grok).

## Agents (gate 3, 2026-11-05)

Fresh agents from three vendors, given only the new Measurement, Computation, Links and Record-Granularity pages,
wrote the energy-axis parts of three records from short sources: a computed OCEAN spectrum calibrated through its
anchor (A), a measured HERFD spectrum with a foil recorded in transmission in the same scan and no cited reference
(B), and a computed FEFF edge energy with no alignment stated (C). The answer key was written before any agent ran.
The old documentation has no field for any of this, so the measure is the key, not an old-versus-new delta; the
change touches no other contract step.

| Item in the key | codex | gemini | grok |
|---|---|---|---|
| A: family BSE; gauge C, anchor, functional with U, magnetic state, radius, core hole | yes | yes | yes, except the radius: stored only in `core_offset_source`, where the source states it (for the anchor) |
| A: calibration standard, `standard_acquisition: none`, feature with definition, 8979.0 eV, source | yes | yes | yes |
| A: `shift_applied_eV` +8811.4 (sign and starting axis) | yes | yes | yes |
| A: base functional in `method.functional_name`, U only in the gauge | no (PBE+U in both) | yes | yes |
| B: HERFD settings in `detection`, standard mode transmission, `same_scan` | yes | yes | yes |
| B: no invented reference source or shift; the gap named in notes | yes | yes | yes |
| C: `as_recorded` with the gap in notes, value kept, family `multiple_scattering`, no gauge | yes | yes | yes |

Changed after the run: Computation says the U is written with the base functional only in the gauge (codex's
miss), and the `standard_record_id` row says a same-scan reference channel usually has no record of its own
(gemini's question). Descriptor names and kinds (codex wrote `edge_energy`, grok `kind: quantitative`) are outside
this change: the kit omitted the Descriptors page. Result: every vendor placed the shift with the right sign and
starting axis, kept the HERFD settings out of the calibration, invented no reference or shift, and kept the
uncalibrated FEFF value.
